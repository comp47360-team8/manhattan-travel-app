# Offpeak - Backend

The Offpeak backend is a REST API built with **FastAPI** that powers the itinerary planning application. It provides authentication, POI management, itinerary generation, and AI-assisted trip planning.

## Installation

Clone the repository and navigate to the backend directory.

```bash
git clone https://github.com/comp47360-team8/manhattan-travel-app.git
cd backend
```

Create a virtual environment.

```bash
python -m venv venv
```

Activate the virtual environment.

### macOS / Linux

```bash
source venv/bin/activate
```

### Windows

```powershell
venv\Scripts\activate
```

Install the project dependencies.

```bash
pip install -r requirements.txt
```

---


## PostgreSQL Setup

Start your local PostgreSQL server.  
Create a database for the project.

```sql
CREATE DATABASE offpeak;
```

Update your environment variables so that the application can connect to the database.

```env
DATABASE_URL=postgresql://username:password@localhost:5432/offpeak
```

Run the database migrations.

```bash
alembic upgrade head
```

---

## Database Seeding

After running migrations, populate the database with the initial POI data, predicted busyness forecast, POI availability modes, POI best-times and POI summaries.

```bash
cd backend/db
psql -d <database_name> -f 03_dml_seed_poi_table.sql
psql -d <database_name> -f 04_dml_seed_busyness_forecast.sql
psql -d <database_name> -f 05_insert_poi_availability_mode.sql
psql -d <database_name> -f 06_dml_update_poi_best_time.sql
psql -d <database_name> -f 07_dml_update_poi_content.sql
```

## Authentication

The backend uses JWT-based authentication.  
Authentication endpoints include:

| Endpoint | Method | Description |
|---|---|---|
| `/auth/signup` | POST | Create a user account |
| `/auth/login` | POST | Authenticate a user |
| `/auth/refresh` | POST | Refresh access token |
| `/auth/logout` | POST | Invalidate session |   

Access tokens are used for authentication. The web client stores tokens using secure HTTP-only cookies, while mobile clients send the access token through the `Authorization` header in HTTP requests.

## Itinerary Generation

The itinerary generation engine uses a deterministic scheduling pipeline to construct personalized travel plans from curated points of interest (POIs). Given a user's trip dates, accessibility requirements, and POI selection, the engine:

1. Retrieves POIs from the database.
2. Filters POIs based on accessibility.
3. Assigns each POI to the least busy available time slot using predicted busyness data.
4. Resolves slot overflows while balancing busyness and geographic proximity.
5. Optimizes the order of visits to minimize travel distance.
6. Returns a complete itinerary with explanations for each scheduling decision.

Unlike the conversational AI component, the itinerary generation process is fully deterministic. The LLM is used only to collect user preferences, while all scheduling decisions are performed by the backend using curated data and rule-based algorithms.


---


## AI Planner

The conversational planner uses:

* **Gemini** as the primary language model for dialogue and preference extraction.
* **Llama (via the Groq API)** as a fallback provider if the primary model is unavailable.
* A deterministic scheduling engine to generate itineraries from curated POIs while enforcing accessibility, opening hours, and user constraints.

## Troubleshooting

### Database connection failed

Ensure PostgreSQL is running and that the `DATABASE_URL` environment variable points to the correct database.

### Missing environment variables

Verify that all required variables have been added to your `.env` file. Missing API keys or JWT configuration will prevent the application from starting correctly.

### Database schema is out of date

If you encounter database-related errors after pulling new changes, apply the latest migrations:

```bash
alembic upgrade head
```

### Module not found

Ensure the virtual environment is activated and all dependencies have been installed:

```bash
pip install -r requirements.txt
```

### Port already in use

If port `8000` is already in use, either stop the process using that port or run the server on another port:

```bash
uvicorn app.main:app --reload --port 8001
```
